Épisode 4 : Intégration holehe — Vérification emails sur 120+ plateformes

📅 24 novembre 2025 • ⏱️ 5 min de lecture • 🏷️ ENRICHED, holehe, Kali Linux, Tests

L'intégration de holehe (outil Kali Linux) dans le système ENRICHED permet de vérifier les emails sur 120+ plateformes pour détecter les comptes actifs. Cette fonctionnalité améliore significativement la qualité de l'enrichissement de contacts.

🎯 Objectif

Lors de l'enrichissement d'un contact, il est crucial de vérifier si l'email trouvé est réellement actif. holehe permet de vérifier sur 120+ plateformes (Amazon, Office365, Twitter, Spotify, WordPress, etc.) si un email est enregistré, validant ainsi sa qualité.

🔧 Intégration technique

L'intégration a été faite dans tous les flux d'enrichissement :

  • ContactEnriched : Enrichissement direct avec holehe
  • ContactFinderLight : Enrichissement automatique des prospects trouvés
  • JobApplicationEnrichmentService : Enrichissement d'annonces avec vérification emails
  • APIs d'enrichissement : Endpoint dédié pour l'enrichissement de prospects

📊 Résultats

Les tests sur des contacts réels montrent des résultats impressionnants :

  • Lucas Tymen : 10 plateformes détectées (Amazon, Codepen, Eventbrite, Firefox, Freelancer, Gravatar, Office365, Replit, WordPress)
  • Sébastien Barillot : 5 plateformes détectées (Firefox, Office365, Spotify, WordPress)
  • Temps d'exécution : 15-30 secondes par email (vérifie 121 sites)
  • Taux de réussite : 100% des tests unitaires et d'intégration passent

🧪 Tests et coverage

Pour garantir la qualité, j'ai créé :

  • Tests unitaires : 5 tests pour ContactEnriched (success, timeout, exception, JSON structure)
  • Tests d'intégration : API prospect email enrichment testée
  • Coverage : 100% des fonctionnalités holehe couvertes
  • Structure JSON standardisée : holehe dans enriched_data['social_accounts']

💡 Apprentissages

Cette intégration a permis de :

  • Améliorer la qualité : Validation des emails sur 120+ plateformes
  • Standardiser le JSON : Structure unifiée pour tous les flux d'enrichissement
  • Gérer les erreurs : Intégration non-bloquante (timeout géré gracieusement)
  • Documenter : Guide complet d'utilisation et API documentation
💡 Apprentissage clé : L'intégration d'outils Kali Linux (holehe) dans un workflow Django nécessite une gestion robuste des timeouts et des erreurs. L'approche non-bloquante permet de continuer l'enrichissement même si holehe échoue, garantissant une expérience utilisateur fluide.

Épisode 1 : La Genèse — De l'idée à l'architecture

📅 24 novembre 2025 • ⏱️ 5 min de lecture • 🏷️ Architecture, Docker, Django

SquidResearch est né d'un constat simple : la recherche d'emploi est chronophage et répétitive. Pourquoi ne pas automatiser ce processus tout en gardant la qualité et la personnalisation ?

🎯 L'idée initiale

L'objectif était de créer une plateforme qui combine plusieurs technologies pour offrir une expérience complète : gestion des candidatures, enrichissement automatique des entreprises, recherche de prospects sur LinkedIn, et automatisation des relances.

🏗️ Choix architecturaux

Dès le départ, j'ai opté pour une architecture microservices avec Docker. Cette approche permet :

  • Scalabilité : Chaque service peut être monté en charge indépendamment
  • Isolation : Les services sont indépendants, facilitant la maintenance
  • Flexibilité : Facile d'ajouter de nouveaux services (n8n, Flowise, etc.)

🔧 Stack technique

Le choix s'est porté sur Django pour le backend (robustesse, ORM puissant, écosystème riche), React pour le frontend (composants réutilisables, état réactif), et PostgreSQL pour la base de données (fiabilité, performances, support JSON).

📊 Premiers défis

Les premiers défis ont été l'intégration de multiples services (n8n, Flowise, Celery) et la gestion de l'enrichissement multi-sources. La solution : un système de cache Redis intelligent et une orchestration optimisée par domaine.

💡 Apprentissage clé : Une architecture bien pensée dès le départ évite les refactorings coûteux plus tard. Prendre le temps de concevoir l'architecture est un investissement rentable.

Épisode 2 : Le Module Enriched — Orchestration intelligente

📅 24 novembre 2025 • ⏱️ 6 min de lecture • 🏷️ Enrichissement, APIs, Cache

Le Module Enriched est le cœur de l'enrichissement des données entreprises. Il orchestre plusieurs sources (INSEE, Pappers, Société.com) pour fournir des données complètes et fiables.

🎯 Problématique

L'enrichissement B2B présente plusieurs défis :

  • Multiplicité des sources : Chaque source a ses propres limites et formats
  • Rate limiting : Les APIs ont des limites de requêtes
  • Qualité des données : Certaines sources sont plus fiables que d'autres
  • Performance : L'enrichissement ne doit pas ralentir l'application

💡 Solution : Orchestration intelligente

J'ai développé un système d'orchestration qui :

  • Groupe les requêtes par domaine : Évite les requêtes redondantes
  • Cache Redis intelligent : Réponses en moins de 0.1s si données en cache
  • Cascade de sources : Si une source échoue, passe à la suivante
  • Rate limiting humanisé : Délais de 5-8s entre requêtes pour éviter les blocages

🔧 Architecture technique

Le module utilise un pattern Factory pour gérer les différentes sources d'enrichissement. Chaque source implémente une interface commune, permettant d'ajouter facilement de nouvelles sources.

📊 Résultats

Avec ce système, l'enrichissement est :

  • Rapide : Cache hit en moins de 0.1s
  • Fiable : Cascade automatique si une source échoue
  • Respectueux : Rate limiting pour éviter les blocages
  • Évolutif : Facile d'ajouter de nouvelles sources

🔄 NOUVEAU : Import CSV Intelligent

Problème résolu : Le module de normalisation ne détectait pas correctement les colonnes CSV, causant 100% d'éléments ignorés lors de l'import.

Solution déployée : Refactorisation complète avec détection automatique intelligente des colonnes :

  • Détection automatique : Reconnaissance de multiples variantes (Entreprise, Société, Nom, Company, etc.)
  • Normalisation intelligente : Transformation automatique vers schéma unifié avant import
  • Recherche multi-champs : Recherche du nom d'entreprise dans plusieurs champs possibles (insensible à la casse)
  • Fallback intelligent : Si nom non trouvé, utilise la première colonne non vide qui ressemble à un nom
  • Nettoyage automatique : Extraction du domaine depuis URLs complètes, suppression de "www."
  • Support multiples encodages : UTF-8, latin-1

Résultats :

  • Avant : 145 éléments ignorés, 0 créés, 0 mis à jour
  • Après : 145 créés, 0 ignorés (100% de succès) ✅
💡 Apprentissage clé : L'orchestration intelligente permet de transformer des APIs limitées en un système robuste et performant. Le cache est votre meilleur ami pour les performances.

🔄 Nouveau : La détection automatique des colonnes transforme l'import CSV d'un processus fragile en une expérience fluide et fiable, même avec des formats de données variés.

Épisode 3 : SEO & Billing — Optimisation et monétisation

📅 24 novembre 2025 • ⏱️ 4 min de lecture • 🏷️ SEO, Stripe, Abonnements

Après avoir développé les fonctionnalités core, il était temps de penser à la visibilité (SEO) et à la monétisation (billing). Deux aspects cruciaux pour une plateforme SaaS.

🔍 Optimisation SEO

L'audit SEO a révélé plusieurs points à corriger :

  • Pages privées indexées : Les pages protégées étaient accessibles aux crawlers
  • Redirections 302 : Plusieurs pages redirigeaient vers login
  • robots.txt incomplet : Certaines routes API étaient bloquées
  • Meta tags manquants : Pas de Open Graph ni Twitter Cards

✅ Solutions mises en place

J'ai implémenté une stratégie SEO complète :

  • robots.txt optimisé : Blocage des pages privées, autorisation des pages publiques
  • sitemap.xml : Uniquement les pages publiques indexables
  • Meta robots : `noindex, nofollow` par défaut, `index, follow` pour pages publiques
  • Canonical URLs : Évite le contenu dupliqué
  • Open Graph & Twitter Cards : Meilleur partage sur réseaux sociaux

💳 Système de billing Stripe

Pour la monétisation, j'ai intégré Stripe avec 6 plans d'abonnement :

  • Gratuit : 5 candidatures/mois pour tester
  • Essai 15 jours : Accès complet sans CB
  • 3 plans Starter/Pro : Prospection, Email Marketing, Réseaux Sociaux
  • Offre Complète : Tout illimité avec économie de 29%

🔒 Sécurité

J'ai également corrigé un problème de throttle sur l'inscription : le rate limiting s'appliquait sur les requêtes GET (clics sur les plans), bloquant les utilisateurs légitimes. Solution : throttle uniquement sur les requêtes POST (soumission du formulaire).

💡 Apprentissage clé : Le SEO et la monétisation doivent être pensés dès le début. Corriger après coup est plus coûteux et peut impacter la croissance.
